# Target verifier and recurrent-state transaction: static code audit

**Exact code snapshot:** [JakeATX/llamAmpere c7a3a742 (2026-09-18)](https://github.com/JakeATX/llamAmpere/tree/c7a3a742f55d76e46a7c4ccfc40bf01a8be318ee). This is newer than the [v0.3 measurement pin 36a6bca81](https://github.com/JakeATX/llamAmpere/tree/36a6bca81). **This document inspects producer+verifier code, not Zephyrus execution.** The linked author's X article is not available as full text; the author-hosted article and source are the primary references.

## 1. Precise p/q eligibility and position-level fallbacks

[`common_sampler_pq_supported`](https://github.com/JakeATX/llamAmpere/blob/c7a3a742f55d76e46a7c4ccfc40bf01a8be318ee/common/sampling.cpp#L918-L937) rejects null samplers, active grammar, active reasoning-budget handler, temperature <= 0 and any nonzero Mirostat. In the [draft producer](https://github.com/JakeATX/llamAmpere/blob/c7a3a742f55d76e46a7c4ccfc40bf01a8be318ee/common/speculative.cpp#L2170-L2310), the effective p/q path additionally requires a configured mirrored per-request sampler, valid draft q-output storage and `pq_params_ok`; when the backend has already sampled a token without retaining its source distribution, that draft position is forced to the identity/argmax fallback. In the [target verifier](https://github.com/JakeATX/llamAmpere/blob/c7a3a742f55d76e46a7c4ccfc40bf01a8be318ee/common/sampling.cpp#L939-L1090), an absent q row or an unavailable CPU target-probability array forces id-match for that position. Calling a run 'p/q MTP' based only on `LLAMA_SPEC_PQ=1` is wrong unless the effective-mode counters show positions taking it.

**Target change needed:** an explicit per-position `verification_mode` enum (pq, id_match, replay, no_draft) and reason counters in telemetry, with no per-token synchronous GPU readback added purely for instrumentation. Keep grammar and constrained tool schemas on the engine's verified safe path until both p and q implement identical constraints, rather than asserting universal exact p/q support.

## 2. Actual verifier is a coupled target-draw algorithm

The implemented code [L950-L1066](https://github.com/JakeATX/llamAmpere/blob/c7a3a742f55d76e46a7c4ccfc40bf01a8be318ee/common/sampling.cpp#L950-L1066) first samples `x ~ p` through the existing target sampler for the row. It looks up the proposed `d` and its `q[d]` in the saved draft probability list and `p[d]` in the target list. It computes `a=min(1,p[d]/q[d])` and **accepts immediately if `x==d`**; otherwise it performs an extra accept test with `r=(a-p[d])/(1-p[d])` where the guard applies. This is not the naive 'always toss one uniform draw against a' pseudocode. Conditioned on d, `Pr[x=d]=p[d]`, and `Pr[extra accept | x != d]=(a-p[d])/(1-p[d])`, so `Pr[accept | d]=p[d]+(1-p[d])*r=a` (provided q[d]>0 and 0<=p[d]<1). On failure it discards x, calculates `R[i] ∝ max(0,p[i]-q[i])`, samples the residual using a separate RNG and breaks out of the draft chain. The target sampler accepts only the emitted `d` or residual token into conversation history. An all-accepted draft samples one additional target token.

The reason the coupled formula is legal is `a >= p[d]` whenever normalized `q[d] <= 1` and `q[d] > 0`. The implementation falls back to x if residual total is numerically zero; this is a last-resort approximation for numerical/pathological states, not proof that mismatched q is safe. For source-verifiable exactness, confirm that `q` was indeed the actual normalized distribution used to draw d, and `p` is the **request-conditioned post-processor distribution** with the same prefix and emitted-token history. q=0 for a supposedly proposed d is invalid and should be logged as an invariant violation in a new implementation. No extra acceptance outside q's shortlist can occur, but residual sampling can produce any target token.

**Independent numerical proof to test:** let `A_i=min(p_i,q_i)` and `S=sum_i A_i`. The accepted-token contribution is `A_i`; rejection probability is `1-S`; the residual law is `(p_i-A_i)/(1-S)` when `S<1` (because `p_i-A_i=max(p_i-q_i,0)`). Therefore emitted law = `A_i+(1-S)*(p_i-A_i)/(1-S)=p_i`, including when q has zero support outside the shortlist. This is a probability law, not a claim of byte-identical stochastic output or MTP speed. The accompanying `tools/spec_math.py` + tests implement this property independently of the upstream C++.

### Detailed source-level hazards still to audit, not hand-wave

- `common_sampler_sample` returns token x and retains post-sampler `cur_p`; confirm normalization and candidate ordering for every permitted chain, including token bias/penalties/top-k/top-p/min-p. The supported-check only excludes grammar/reasoning budget/Mirostat/greedy; that is not sufficient by itself to prove every custom sampler yields matching p and q.
- The verifier's `q_of` is currently a linear scan through draft candidates, executed inside a loop over target candidates to compute overlap/residual, then again for residual sampling. This costs up to O(|p|·|q|) host-side work per checked position. On a 64K q shortlist and large target vocab the upper bound is alarming; the effective `cur_p`/q candidate sizes and CPU time must be inspected before proposing optimization. **Potential code improvement:** one reusable token-ID-indexed sparse scratch map or sorted two-pointer merge for q lookups per draft position, avoiding allocations per round. This is a static complexity observation, not evidence it is a dominant Zephyrus bottleneck.
- On rejection the code calculates the residual twice (total then cumulative selection). A compact precomputed normalized q lookup and one well-defined residual traversal could reduce host cost, but optimization must preserve floating-point precision, RNG consumption behavior and token distribution. Do not silently claim byte-exactness when changing operation order or RNG calls.
- `replay && i+1 == draft.size()` accepts a previously recorded final token from a replayed draft after a target sample; the surrounding server replay transaction must be audited to confirm this is an already-committed outcome and cannot bypass fresh verification after a changed prefix.
- The code may accept d even when `q[d]==0` if `x==d` first; that state should be impossible for a valid q draw. Treat it as an instrumentation/assertion target to catch mismatched draft-list bookkeeping.

## 3. Recurrent GDN state must commit atomically with verification

Qwen3.8-27B has 48 recurrent Gated DeltaNet layers and 16 conventional attention layers; the recurrent state is not a per-token ordinary attention KV array. [Author's original v0.3 article](https://github.com/JakeATX/llamAmpere/blob/36a6bca81/docs/llamampere-v0.3/ARTICLE.md) describes RB1/RB1b fixes: on short ubatches, only `min(n_seq_tokens,K)` of K snapshot slots are newly valid and rollback cannot read beyond that bound. It explicitly listed `LLAMA_GDN_REPLAY=1` as still failing **at that release**.

**Important update:** [2026-09-18 PR #8, merged at c7a3a742](https://github.com/JakeATX/llamAmpere/pull/8) repairs the opt-in replay state serialization: checkpoint state and an ingredient ring accompany the state blob; a restored sequence reconstructs from checkpoint+ring on its next decode. It also fixes wildcard `seq_rm(-1,...)` handling and stale snapshot groups after short ubatches. The published PR describes CPU/GPU rollback gates and matching greedy output in its tests. Those are upstream-reported tests, **not** tests run by Zephyrus Local AI. A fork based on v0.3 alone would omit them; any new direct EXL3 runtime integration needs the repaired state lifecycle or its equivalent.

Minimal correctness state-machine matrix for the port: prompt fill → draft 1..4 → (accept all | reject first | reject intermediate | reject last) → truncate ordinary KV and roll back recurrent snapshot to accepted prefix → next token; repeat across short ubatch (1), regular ubatch, sequence copy, sequence wildcard removal, prompt-cache checkpoint save/reload, partial edit/replay, EOS, context-eviction and request cancellation. Assert equality of emitted **token IDs and actual logits within a stated tolerance** against a non-speculative reference for deterministic fixtures, while separating legitimate floating-point near-tie differences from incorrect recurrent rewinds. A greedy hash alone is an incomplete proof across all states.

## 4. Engineering decision before changing CUDA

A fast target-verifier rewrite might be reusable across GPU generations, but only after measuring host cost with correct effective p/q path. A fast trellis kernel cannot repair recurrent-state corruption or a wrong residual law. Keep the speculative state transaction in a well-defined engine adapter; put reusable mathematical tests, state-transition trace schemas and independent output-quality gates above all GPU-specific code. Preserve author's MIT attribution where integrating real implementation files, not merely linking the source.
